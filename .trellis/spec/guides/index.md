# 思考指南

> **目的**：在编码前扩展检查视角，捕捉容易漏掉的问题。

---

## 为什么需要思考指南？

多数 bug 和技术债不是因为能力不足，而是因为“没想到”：

- 没想到层边界会发生什么 → 跨层 bug
- 没想到代码模式会重复 → 到处复制粘贴
- 没想到边界场景 → 运行时错误
- 没想到后续维护者 → 代码难读

这些指南帮助你在编码前问对问题。

## 快速触发条件

### 何时思考跨层问题

- [ ] 功能触达 3 层以上（API、Service、Component、Database）
- [ ] 数据格式在层之间发生变化
- [ ] 多个消费者需要同一份数据
- [ ] 不确定某段逻辑应该放在哪里

→ 阅读 [跨层思考指南](./cross-layer-thinking-guide.md)

### 何时思考代码复用

- [ ] 正在写与现有代码相似的逻辑
- [ ] 看到同一种模式重复 3 次以上
- [ ] 正在给多个地方添加同一个字段
- [ ] **正在修改任何常量或配置**
- [ ] **正在创建新的 utility/helper function** ← 先搜索！

→ 阅读 [代码复用思考指南](./code-reuse-thinking-guide.md)

---

## 修改前规则（关键）

> **修改任何值之前，必须先搜索！**

```bash
# 搜索你准备修改的值
grep -r "value_to_change" .
```

这个习惯可以避免大多数“忘了同步更新 X”的 bug。
