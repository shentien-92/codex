# 前端项目接入 CI 域判断清单

## 核心口径

- CI 域不依赖项目类型
- 任意前端项目都可以安装 CI 域并执行相关命令
- 判断重点不是“这个项目属于哪个开发域”，而是“这个项目是不是前端项目，以及是否需要这些质量门禁”
- `ci:uni-test` 目前只支持 `jest` 和 `mocha`

## 最小接入路径

1. 确认当前仓库是前端项目
2. 在项目根目录执行 `kjl task install ci`
3. 检查 `def.config.js` 中是否出现 `ci:*` 任务
4. 如果要接入单测门禁，先确认测试框架是不是 `jest` 或 `mocha`
5. 选择先做本地卡点，还是同时接入 GitLab CI / Moon

## 常见误区

- 误以为只有 DEF 项目才能安装 CI 域
- 误以为必须先属于某个特定开发域，才能执行 `ci:*`
- 误以为 `ci:uni-test` 可以直接运行任意测试框架
- 把 CI 域问题回答成通用 CI 平台教程，反而丢掉了 `kjl` 命令和知识页里的具体能力

## 最小质量门禁

多数前端项目优先考虑：

- `kjl ci:lint`
- `kjl ci:uni-test`
  前提：测试框架为 `jest` 或 `mocha`
- 本地 `kjl ci:init`

按需增强：

- `kjl ci:copyright`
- `kjl ci:gpl`
- `kjl ci:mutation-test`

## 输出方式

审查一个前端项目时，优先回答：

- 是否已安装 CI 域
- 已有哪些 `ci:*` 任务
- 缺了哪些关键门禁
- 下一步最小接入动作
